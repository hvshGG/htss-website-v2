# Размещение HTSS

Сайт поддерживает два режима: Node.js с отправкой заявок через SMTP и обычный статический хостинг. Для отправки заявок без почтовой программы посетителя используйте Node.js. Подходят VPS или платформа с постоянным Node-процессом; одного FTP-хостинга для этого недостаточно.

## Node.js и SMTP

Нужен Node.js 24 LTS. Команды выполняются из корня проекта:

```sh
npm ci
npm test
```

Скопируйте `.env.example` в `.env` и заполните:

| Переменная | Значение |
| --- | --- |
| `CONTACT_TO` | Действующий адрес, на который компания получает заявки. Без него приём отключён. |
| `CONTACT_FROM` | Подтверждённый адрес отправителя у почтового провайдера. |
| `SMTP_HOST`, `SMTP_USER`, `SMTP_PASS` | SMTP-реквизиты почтового провайдера. |
| `SMTP_PORT`, `SMTP_SECURE` | Обычно `587` и `false` для STARTTLS; либо `465` и `true` для TLS. |
| `PUBLIC_ORIGIN` | Публичный адрес сайта, например `https://example.kz`, без пути. |
| `SITE_URL` | Окончательный HTTPS URL сайта для canonical и Open Graph при сборке. Пока домен не выбран, оставьте пустым. |
| `PORT` | Порт Node-процесса, по умолчанию `3000`. |
| `HOST` | По умолчанию `127.0.0.1` для reverse proxy на том же сервере; для контейнерной платформы обычно `0.0.0.0`. |

Затем:

```sh
npm run build
npm start
```

Скрипт запуска читает `.env`, если он существует. На платформе можно задать эти переменные в панели хостинга вместо файла. Секреты не должны попадать в `site-config.js`, HTML, `dist`, Git или клиентский JavaScript. Если пароль однажды попал в публичный репозиторий, замените его у почтового провайдера.

Сервер автоматически раздаёт `dist`, если там есть `index.html`; иначе файлы из текущей рабочей папки. Для явного выбора задайте `PUBLIC_DIR` — абсолютный путь или путь относительно рабочей папки. После изменения исходников повторите `npm run build` и перезапустите процесс. Для локальной разработки `npm run dev` всегда раздаёт исходники; после правки HTML/CSS обновите страницу. Включите автоматический перезапуск Node-процесса средствами хостинга.

Публичный трафик должен идти через HTTPS. В reverse proxy укажите публичный `Host`, а в `PUBLIC_ORIGIN` — адрес с `https://`. Сервер использует этот адрес для проверки запросов формы и включает HSTS. Не перенаправляйте на Node весь файловый каталог: открытым должен быть только HTTP-порт приложения через proxy. Для прямого доступа на локальном компьютере `PUBLIC_ORIGIN` можно оставить пустым.

Ограничение формы — пять попыток за десять минут на IP; данные лимитера хранятся только в памяти процесса. За reverse proxy без дополнительной настройки все посетители имеют IP прокси и делят лимит. Для одного доверенного прокси, который перезаписывает `X-Forwarded-For` адресом посетителя, задайте `TRUST_PROXY=true`; прямой доступ к Node тогда необходимо закрыть. Для нескольких экземпляров приложения нужны общий лимитер или ограничения на уровне хостинга/WAF.

`GET /site-config.js` формируется сервером из переменных окружения. При полной SMTP-конфигурации он включает `POST /api/contact`. Сервер проверяет ввод, согласие, размер тела, источник запроса и лимит попыток. Он не сохраняет заявки на диск и возвращает успех только когда SMTP-сервер принял письмо для нужного получателя. Принятие SMTP не гарантирует попадание во входящие: проверьте SPF/DKIM/DMARC, папку «Спам» и журнал провайдера. При ошибке форма сохраняет введённый текст и даёт повторить отправку.

Если настроен только `CONTACT_TO`, форма открывает черновик письма в почтовой программе посетителя; это **не отправленная заявка**. Если адрес не задан, сайт предлагает звонок. При неполной SMTP-конфигурации `/api/contact` возвращает `503` и не принимает данные для последующей отправки.

Перед публикацией отправьте одну реальную тестовую заявку со своего адреса/телефона и убедитесь, что письмо пришло на нужный ящик. Автоматические тесты используют имитацию почтового транспорта и не отправляют письма.

## Статический хостинг

Выполните `npm ci` и `npm run build`, затем загрузите **только содержимое `dist`** в публичную папку хостинга. Исходники сервера, `.env`, `node_modules`, тесты и файлы Git публиковать не нужно.

В исходном `site-config.js` укажите проверенный контактный email перед сборкой. Оставьте `contactEndpoint` пустым и `delivery: 'email'`: форма подготовит черновик в почтовой программе. Статический хостинг сам по себе не отправляет письма и не подтверждает доставку.

Если у хостинга есть собственная серверная функция, можно подключить её через `contactEndpoint` и `delivery: 'smtp'`. Обработчик должен поддерживать тот же JSON-контракт: `{name, phone, sector, message, consent: true, website: '', language}`; `sector` — `prom`, `comm`, `log`, `eng` или `other`; `language` — `ru`, `kk` или `en`. Возвращать HTTP `200` с `{ "ok": true }` можно только после подтверждения приёма письма. Ошибки возвращаются с соответствующим HTTP-статусом и `{ "ok": false, "code": "…" }`. Сохраните проверки согласия, валидацию, лимиты и защиту от межсайтовых запросов. Для такого обработчика предпочтителен адрес на том же домене `/api/contact`, чтобы не ослаблять CSP и CORS.

На статическом хостинге настройте HTTPS и security headers в его панели: `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: DENY`; CSP соответствует заголовку в `server.mjs`. HTML и `site-config.js` должны обновляться без долгого кеширования; для `assets` подходит `Cache-Control: public, max-age=3600, must-revalidate`.

## Проверка после размещения

- Страница, шрифты, фото и видео загружаются по HTTPS без ошибок консоли.
- Меню, переключение языка, диалог и поля работают на телефоне и с клавиатуры.
- Указаны правильные email, телефон и юридические сведения; прочитана политика обработки данных.
- Реальная заявка достигает получателя; при отключённом SMTP нет ложного сообщения о доставке.
- Адреса `/.env`, `/.git/config`, `/package.json` и `/server.mjs` возвращают `404`.
- Установлены корректные домен и метаданные для поиска/соцсетей. Заполните `SITE_URL` и пересоберите сайт: canonical и Open Graph появятся автоматически. Если понадобится sitemap, его можно добавить после выбора окончательного домена.
